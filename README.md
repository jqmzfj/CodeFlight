# CodeFlight

CodeFlight 是一个轻量的原生开发工作台，项目地址为 [github.com/jqmzfj/CodeFlight](https://github.com/jqmzfj/CodeFlight)。

## 更新

应用设置中的“更新”会检查 GitHub Releases。发现新版本后，用户可以查看版本说明并选择下载 DMG；安装过程由用户确认。发布 macOS 版本时使用 `CodeFlight-macOS.dmg`，后续 Windows 版本可在同一个 Release 中添加 Windows 安装包，客户端更新协议保持不变。

CodeFlight 是一个原生 macOS 开发工作台，面向希望用轻量工具替代大型 IDE 的开发者。它把项目切换、文件预览、Git 管理和运行命令集中在一个窗口中。

当前开发范围仅限 macOS，Windows 版暂不开发。

代码预览支持在“设置 → 编辑器”中调整 11–20pt 字号，字号会同步应用到大文件预览和冲突编辑器；预览缓存会按字号隔离，避免复用错误的排版结果。

当前版本：`0.4.48`

运行工具：顶部支持运行／重跑与跨项目停止菜单（单个／全部），⌘R运行当前配置、⌘.停止当前项目。启动后自动打开运行会话并选择独立日志，支持筛选、复制、清空、跟随输出与关闭已结束会话。重跑保留原启动命令、目录和环境，等待旧进程组退出，停止可取消待重跑请求。

运行配置支持从项目脚本追加导入，防止重复导入；打开配置时读取磁盘最新版本，损坏或标识重复时拒绝覆盖。环境变量按字面值保存，支持换行、引号和反斜杠。关闭和退出时保护未保存草稿；退出会取消待重跑请求并清理托管进程。Git 操作拥有独立操作记录，不覆盖运行日志；临时认证值及诊断中的地址凭据会过滤后显示。

终端（⌘2）采用原生 SwiftTerm + PTY：可输入命令、交互式读取、Ctrl+C、Tab 补全、颜色输出，支持同一项目多个终端会话。首次打开按需启动本机登录 Shell，默认进入项目目录；切换项目或收起面板保留会话。每会话保留2000行滚动历史，关闭会话／项目和退出时清理对应终端进程。Git 面板提供“提交日志／操作记录”切换。终端会话不跨应用重启恢复。

主要工作区支持拖动分隔线调节尺寸：侧栏、底部工具窗口、Git 日志三栏、差异双栏、进程列表与输出，以及 Git／运行配置窗口。同步、克隆、提交引用、修改提交和跟踪分支窗口也支持原生拖动调整，并保留明确的关闭／取消／完成操作栏。各区域保留最小可用宽高，分别记住尺寸；双击分隔线恢复默认。缩小窗口时暂时收缩，放大后恢复偏好尺寸。

## 构建

需要 macOS 13 或更高版本，以及 Swift 6.2+（Xcode Command Line Tools）：

```bash
swift build
./scripts/package-app.sh
./scripts/runtime-smoke-test.sh
```

生成的 App 位于 `CodeFlight.app`。要生成分发包：

```bash
./scripts/package-release.sh
```

ZIP 和 DMG 会输出到 `release/`。当前脚本使用 ad-hoc 签名；正式发布前需要替换为 Developer ID 签名并完成 notarization。

如果只是自己或团队内部使用，直接打开 `release/CodeFlight-macOS.dmg`，将 App 拖入“应用程序”即可。首次打开时如果 macOS 提示来源未验证，可在“系统设置 → 隐私与安全性”中允许打开；内部使用不需要 Apple 公证。

`package-release.sh` 会分别构建 arm64 和 x86_64，并使用 `lipo` 生成 Universal 2 App，Apple Silicon 和 Intel Mac 都可以使用同一个安装包。

有 Developer ID 证书和 `notarytool` Keychain Profile 后，可以执行正式签名与公证：

```bash
DEVELOPER_IDENTITY="Developer ID Application: Your Name (TEAMID)" \\
NOTARY_PROFILE="codeflight-notary" \\
./scripts/sign-and-notarize.sh
```

## 项目数据

最近打开的项目路径、语言和主题保存在 macOS UserDefaults。项目运行配置保存在项目目录的 `.git-workbench/run-config.json`，可纳入或排除项目版本控制，按团队习惯决定。

## Git 与命令

Git 操作通过本机 `git` CLI 执行，运行命令通过登录 zsh 环境执行，因此会继承 nvm、fnm、pyenv 等常见开发环境。所有项目进程按项目隔离，关闭项目或退出应用时会停止对应进程。

切换项目时，文件树、Git 状态、分支／历史／远程元数据和项目命令探测会并行读取；每次结果都按项目标签和刷新请求校验，旧项目的慢查询不会覆盖当前项目。切换只读取当前项目，不建立跨项目的全量文件或 Git 索引。


## 常用交互

分支列表的切换只作用于所选本地分支，不自动猜测远程分支。外部删除分支后再次点击旧条目会失败并保留同名文件的本地修改；切换远程分支需显式选择对应远程条目。分支名称按字面名称验证，不接受参数或历史切换简写；新建分支的指定起点先解析为提交。

提交面板中，单击文件或用方向键选择文件即可在主区域查看差异；勾选文件进行暂存，取消勾选则取消暂存。列表支持筛选、分组折叠和右键操作，提交消息和提交按钮固定在底部。一个文件同时存在已暂存和未暂存内容时，两组分别显示，右侧可切换比较范围。差异支持双栏与统一视图切换；普通文本修改可按修改块暂存或取消暂存，操作前会验证预览仍与当前差异一致。未暂存普通文本差异可确认后“回滚此块”，保留其他修改块及暂存内容；回滚不超过 8 MB 的 UTF-8 文件，保持现有 LF／CRLF 与末尾换行状态，拒绝混合换行、内容过滤和过期差异。新文件、删除、重命名、模式变更和二进制文件按整份文件操作。双栏与统一差异保留代码语法颜色。

提交面板右上角“更多”提供“修改最近一次提交（Amend）”。可以只修改上次提交说明，也可以补入已暂存内容，未暂存文件保持原状。窗口打开后若 HEAD 已变化，必须重新打开再操作；合并、变基等未完成时禁用。Amend 会改写历史，已推送的提交应先与协作者确认。

Git 历史停靠在底部，可通过时钟按钮切换到 Reflog 操作记录，从重置或变基前的提交恢复出新分支，保留当前工作区。使用原生连线显示提交与合并关系，可切换当前分支或所有分支。选择提交后，右侧显示该次提交的文件，选择文件会在主区域显示历史差异，不打开模态窗口。普通操作失败会显示可关闭的通知，可展开控制台查看完整输出。回滚、强制删除等破坏性操作仍会确认。

历史记录右键支持从所选提交新建分支；撤销、拣选和重置会预填所选提交，读取并确认目标后执行。合并提交撤销／拣选需要明确选择主线父提交，未选择时不能执行。操作失败保留输入；产生冲突时可关闭表单进入冲突处理，再继续或中止。变基、拣选和撤销提交进行中，提交面板还提供“跳过当前提交”，确认后放弃当前提交并继续后续队列，可用于处理空拣选；普通合并不提供跳过。

历史提交右键的“交互式变基此提交之后…”可编辑当前分支中基准之后的提交；列表从上到下执行，支持上下移动、保留、改写说明、Squash、Fixup 和丢弃。基准自身不改写。开始前需确认改写历史，工作区与暂存区必须干净；执行时重新校验分支及 HEAD，外部变化会拒绝旧计划。当前支持最多 200 个线性提交；含合并关系的范围会明确提示，不自动展开合并。Squash 默认保留两次说明，完成后可通过 Amend 调整。冲突后可关闭窗口进入已有冲突处理，再继续、跳过或中止；Reflog 可找回改写前的提交。

底部工具窗口默认收起，并记住最后打开的面板与开关状态；运行命令时自动显示控制台输出。`⌘J` 或再次点击已选中的工具图标可以收起／恢复当前工具窗口，恢复时保留工具类型、终端会话和分栏高度。各面板的更多菜单提供对应操作，Git 历史刷新会重新读取历史。点击当前项目标签保留文件与预览状态；关闭当前项目后切换到右侧相邻标签，右侧没有标签时切到左侧。不同项目的提交草稿在当前会话中独立保存，关闭项目后释放。

文件树右键提供查看差异、暂存／取消暂存、文件历史和逐行追溯（Annotate），以及复制路径和在 Finder 中显示。 文件树和提交列表的未跟踪文件右键提供“忽略此文件”，为该文件生成带根锚点的精确规则，自动转义空格、通配符和方括号。优先追加到最近的已有 .gitignore，避免子目录反向规则覆盖；没有时使用仓库根 .gitignore。保留原文件、已有规则和暂存区，规则作为普通未暂存修改供检查。含换行的文件名、冲突或非 UTF-8／超过 1 MB／符号链接的 .gitignore 需手动处理。文件历史复用底部 Git 窗口，按页读取，跟随重命名；选择旧提交时会使用当时的文件路径显示差异。点击“仓库历史”返回整个仓库的记录。

分支弹层顶部的“标签”打开标签管理，可搜索、查看、创建轻量／附注标签，并指定目标提交或分支。支持单独推送所选标签，远程存在不同内容时拒绝覆盖；删除只作用于本地标签并需要确认。切换标签前提示分离 HEAD，工作区有冲突修改时由 Git 拒绝切换。外部移动标签后，旧详情拒绝继续删除、切换或推送，刷新后再操作。

其他本地或远程分支右侧的菜单提供“与当前分支比较”。可以比较两个分支端点，或查看从共同祖先到目标分支的改动；左侧筛选文件，右侧查看双栏／统一差异。比较只读，显示两侧独有提交数，并固定提交快照；外部改变分支后点击刷新更新。

远程分支菜单提供“删除远程分支”，确认窗口显示目标和最近获取的提交。远程有新提交时拒绝删除，需先 Fetch 检查；本地分支和工作区保留。推送地址改变、配置多个推送地址时会拒绝执行。远程默认指针不会列入可操作分支。

推送窗口支持可选的“强制推送（带提交校验）”，用于 Amend／变基后更新远程历史。默认关闭；开启后显示推送地址、本地提交和预期远程提交。服务器有新提交、本地提交或目标改变时拒绝继续；没有远程跟踪记录的新分支使用普通推送。推送期间锁定目标和方式，避免状态混淆。

分支弹层底部的更多菜单可进入“工作树”，查看共享仓库的独立工作目录。支持以新分支、现有分支或分离 HEAD 创建，并作为项目标签打开。工作目录由你指定；移除前确认，有未提交内容、锁定状态或仍在项目标签打开时拒绝移除，分支保留。主工作树不能在此移除或移动。关联工作树支持移动到指定新目录，移动会保留暂存、未暂存、未跟踪及忽略文件，并更新 Git 登记；已打开的工作树需先关项目标签。目标必须尚不存在，且不能在原目录或 Git 数据目录内。失败保留目标输入，成功选中新路径，可直接作为项目打开。Git 不支持移动含子模块的工作树，此时保留原目录并显示原因。详情支持锁定／解锁，可填写锁定说明；锁定适合临时断开的外接磁盘，防止工作树被移除或清理。左下角清理按钮列出失效目录，确认后仅清理 Git 登记并保留分支，锁定记录与现存目录保留；执行前重新校验列表，外部变化需刷新确认。


分支弹层底部的更多菜单提供“子模块”：按需读取路径、地址和父仓库索引中的固定提交，可初始化／更新、同步地址，并将已初始化的子模块作为独立项目打开。默认包含嵌套子模块；更新检出固定提交，不追踪远程最新分支，不强制覆盖本地修改。支持本机 Git／SSH 配置与临时 HTTP 凭据。 左下角 + 可添加子模块，输入源地址与仓库内相对目录；失败保留输入以便重试。详情可移除子模块，操作前确认，存在修改、未跟踪／忽略文件、不同检出提交或仍作为项目打开时拒绝移除。添加和移除会暂存父仓库中的对应更改，仍需提交；移除保留父仓库内的 Git 对象历史。

冲突编辑默认逐块显示当前／传入内容，保留语法颜色；可前后切换冲突块，采用一侧或按指定顺序采用两侧，并撤销上次选择。其他区域保留 Git 自动合并的内容。合并结果可以手动编辑，清除全部标记后才允许保存并标记解决；保存前仅修改当前草稿。可显式切换到整份版本操作，避免最后一个块解决后误点替换整份文件。支持 diff3、CRLF 和自定义冲突标记宽度；无法可靠识别的标记请手动处理。

## Git 冲突与同步

冲突文件单独分组，点击后在主区域比较当前版本、传入版本及共同祖先，并编辑合并结果。保存时会检查残留冲突标记，以及磁盘文件和 Git 索引是否已被其他程序修改；存在变化时拒绝覆盖。修改／删除冲突可以选择保留文件或删除文件。处理结束后通过提交面板中的“继续”完成合并、变基、拣选或撤销；“中止”会先确认。

冲突编辑限制为 2 MB 的 UTF-8 普通文件。二进制、符号链接及更大文件可以整份选择一方，或在外部解决后标记。离开有未保存结果的页面或退出应用时会确认。

文件菜单中提供“克隆仓库”，项目标签旁的加号右键菜单也可进入。使用本机 SSH／Git 凭据，也可以展开 HTTP 身份验证，输入仅供本次操作的用户名和密码／访问令牌。临时凭据不会写入仓库地址、Git 配置或系统凭据存储。克隆与远程仓库编辑拒绝地址中包含 HTTP 用户信息、密码或查询令牌，统一使用临时认证或本机配置。远程仓库窗口提供刷新、保存反馈；外部改变地址后旧详情拒绝继续覆盖或移除，刷新后再编辑。操作期间禁止关闭或切换条目。Fetch 图标右键可选择远程仓库并填写临时凭据。

Stash 管理提供说明、包含未跟踪文件、保留已暂存修改和内容预览；“应用”保留原 Stash，可选择恢复原暂存状态，“丢弃”会确认。保存失败时保留说明，错误在当前窗口显示；成功后选择新 Stash。窗口内可刷新外部新增或删除的记录；外部改变序号后旧操作会拒绝，刷新后重试。

## 运行配置与文件刷新

顶部选择运行配置后，“运行”和 ⌘R 会使用该配置的命令、工作目录和环境变量。运行配置窗口支持新增、复制、重命名和删除，保存前的修改只保留在窗口中，取消不会改动项目配置。多个配置可同时设置自动运行，进程按项目管理。

运行命令读取交互式登录 zsh 配置，包括 `.zprofile` 与 `.zshrc`；配置中指定的环境变量优先于 shell 初始化文件。开发环境检测只初始化一次 shell，探测和 Docker 列表请求有超时限制。停止进程会结束该命令的进程组，包括派生的开发服务；退出应用会停止由应用启动的命令。

目录按需加载，收起时释放子目录列表，刷新时保留展开路径，仅重读可见展开目录。预览缓存检查磁盘大小、修改时间和文件标识，外部编辑或原子替换后不继续使用旧缓存；重新激活窗口时刷新当前项目。缓存上限 64 MB，大文件只读取有限前缀；分行在后台完成，渲染按 10,000 行递增加载，最多预览 100,000 行。超过 32 KB 的单行显示截断提示，避免压缩产物造成过大的文字排版。单个目录最多列出 5,000 项，文件搜索最多返回 200 项；Git 状态输出最多 16 MB，超过时显示明确错误，避免误报没有更改。

### 0.3.13 交互修复

新建、重命名、Reflog 恢复分支，以及撤销／拣选／重置表单均在 Git 成功后关闭；失败保留输入并在当前窗口显示可滚动的错误输出，支持修改后重试。执行时显示进度并锁定重复提交及关闭操作。分支表单支持自动聚焦、回车提交与 Esc 关闭。

项目切换自动滚动到当前标签，并清除上个项目的文件筛选和文件内搜索。设置改为随内容自适应高度，图片背景显示正确的选中状态、文件名及更换入口，取消选图保留原背景。

### 0.3.14 刷新与进程生命周期

刷新已打开的文件和差异时保留当前预览，内容未变则不重新发布文本，减少闪烁并保留滚动位置。手动关闭的文件不会在刷新后自动打开；磁盘删除当前文件后关闭预览。

关闭有运行命令的项目会提示“取消”或“停止并关闭”，仅停止该项目的进程；Esc 取消。Git 正在执行时暂不允许关闭该项目。运行后立即停止会阻止尚未启动的任务，主动停止的命令显示“已停止”。所有命令均登记到进程管理器，包括未指定项目或任务 ID 的 Git 与环境检测命令，以便退出时清理。

开发环境和 Docker 检测独立于仓库刷新，同类检测进行中合并重复请求；切换项目不会丢弃机器环境检测结果，检测也不再延长 Git 的忙碌状态。

逐行追溯按需读取当前文件，显示作者、日期、提交哈希与语法着色的代码行；当前未提交行单独标识。选中行后可查看对应提交差异，跟随重命名前的历史路径；支持刷新、Esc／关闭退出。仅支持仓库内不超过 1 MB、10,000 行的 UTF-8 普通文本，输出限制 8 MB、命令时限 20 秒，不缓存整个仓库。

更改列表支持 ⌘ 多选、Shift 连选，右键或“所选操作”可批量暂存、取消暂存、回滚。混合选择按操作分别显示适用数量；刷新和筛选会清除失效／隐藏选择。分组按钮只操作当前筛选组，顶部“暂存全部”仍明确作用于全部更改。回滚需确认路径，保留暂存版本；过期状态、冲突和子模块会拒绝批量回滚。超长路径列表需分批执行。

提交面板与分支菜单显示当前跟踪分支及领先 ↑／落后 ↓ 提交数；分离 HEAD、尚无提交、未设置跟踪和跟踪引用失效分别提示。数量基于本地已获取引用，Fetch 后随项目刷新更新；不会自动访问网络。两侧计数均为零显示“已获取版本一致”，不表示已检查服务器最新状态。

当前本地分支的更多菜单提供“设置跟踪分支”：选择已 Fetch 的远程分支或“不跟踪”，仅修改本地上游配置。窗口支持刷新、关闭和 Esc；外部切换分支或修改上游后，旧表单会拒绝保存，刷新后重试。

分支比较窗口支持“文件差异／当前分支独有／目标分支独有”切换。独有提交按 50 条分页，支持筛选已加载的说明、作者和哈希；选择提交后按需读取其文件与差异，可切换双栏／统一视图。记录使用比较时的提交快照，刷新比较才更新分支端点，不建立整个仓库索引。

仓库历史提供独立刷新入口，分页期间校验 HEAD 与分支引用是否变化。发生变化时保留当前列表并提示刷新；读取失败显示错误和重试，不将失败当作空历史。每页 50 条，仅读取一条额外记录判断是否还有下一页。

历史详情和分支比较中的提交详情共用有界读取：说明最多 256 KB、文件列表最多 2 MB。读取失败或截断会显示错误与重试，只有成功读取的空提交才显示“没有文件变更”。

文件历史分页固定使用本次读取的起点提交，外部新增提交或切换分支不会令后续页错位；刷新文件历史或项目后更新起点。仍沿重命名追溯历史路径，读取失败保留已加载记录与分页位置，可在固定底部操作栏重试。损坏的 HEAD 或失效快照会显示错误，不作为无提交仓库处理。

## 预览性能测量

运行 `./scripts/measure-preview-performance.sh`，在工作区根目录创建并自动清理专用样本，用实际预览源码构建优化的独立组件探针，每个样本用新进程测量3次。结果写入 `.build/preview-performance/latest.json`，涵盖读取、后台文本准备、首屏／中部／末尾绘制和进程RSS。它不测冷磁盘缓存、真实输入延迟或整个应用的内存；请结合实际窗口验收，不能用这些结果代表所有项目。

Git 提交日志使用原生多列表格，提交、作者、哈希和日期可拖动列边界调整宽度。刷新未变化的历史时保留已加载页及选中提交；引用变化时重新读取首屏，避免混合不同历史快照。列宽目前不跨应用重启保存。
