# 0.4.29 Unicode标识符着色

## 问题

0.4.28实际十万行文件截图显示：值50000中的数字后缀被当数字字面量着色。旧数字边界只排除ASCII字母／数字／下划线，不能识别中文、组合字符、emoji和美元符号标识符；数字后没有边界时也会错误着色无效字面量的前缀。

## 修改

两组轻量lexer均按Unicode字母／组合标记／数字／连接符／其他符号／修饰符号以及美元符号限制数字的前后边界，保留独立十六进制／整数／小数的颜色。仍为预览用词法着色，不声称提供IDE语义分析。

## 证据

- 新增两项回归通过，覆盖swift／js／php／py／sh中的中文、带重音、分解组合字符、emoji、美元符号和ASCII数字后缀；标识符每个UTF16位置保持默认色，独立数字仍为数字色，无效数字前缀不误着色。日志.build/production-069-syntax-tests.log。
- 正式274项全量0失败163.271秒；双架构／签名／启动／UUID／ZIP／DMG通过，日志.build/production-069-release.log。
- 最终0.4.29(72)App、ZIP内程序及发布身份哈希一致：81e09eec296a181b837aec7f2ead3d9990286b4dfdf4c8a622e4e41970c9ce3a。
- 尝试CUA启动最终App时Mac再次锁屏，未实际查看修复后的文字颜色；因此最终原生颜色复验仍待继续。本轮没有创建新的着色夹具或更改业务文件。
- 上一版实际主App性能样本见QA-0.4.28.md及main-preview-performance-0.4.28.json，范围和局限均保留。

整体目标未完成，其他语言的多行词法状态／实际输入法、多项目并发交互、完整窗口矩阵与更多真实性能样本仍需继续。
