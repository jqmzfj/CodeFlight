不能用一次构建成功或一张截图证明整个产品达标。下面每一项需要与其范围相匹配的源码、测试、运行和界面证据；空白项不视为完成。

当前交付构建0.4.47(90)：306项全量、两架构与包身份通过；主窗口最低内容尺寸由 AppKit 原生维持，并合并重复尺寸检查任务；左侧工具栏宽度支持36–72pt拖动并持久化；底部工具窗口支持平滑展开／收起并分别保留高度；文件树目录异步展开有读取状态，Git 状态着色扫描减少临时分配。双栏分隔线在视口内，修复可访问性调整时跳转顶部，修改块操作／说明分列，最终App中浅色／英深色180pt左右下限复验通过。Git 同步、克隆、提交引用、修改提交和跟踪分支窗口统一接入最小尺寸与可拖动调整；项目切换的独立 Git 只读查询已并行执行。编辑器字号已支持 11–20pt，并纳入预览准备、Core Text 宽度测量、TextKit 行高、滚动定位和缓存键，字号切换不会复用旧排版。主题菜单现在可明确选择系统／浅色／深色，顶部和编辑器标签的装饰图标已从 VoiceOver 语义树隐藏，避免重复朗读或误读为“移动”；发布脚本会从本轮 Universal 二进制自动重建 App，避免安装包复用旧代码。双栏／统一切换的逻辑阅读位置保持、真实触控板手势、完整窗口视觉矩阵、真实IME／VoiceOver及更多项目压力仍待验收。当前只开发macOS，Windows版本暂停。

## 0.4.5 预览准备与性能基准

- 实测瓶颈：十万行中英／emoji样本磁盘读取约3ms，原后台准备约2.84秒；中部／末尾的连续TextKit排版约2秒。不能把读盘或首屏结果当作完整滚动体验证明。
- Unicode宽度测量改为分块共用Core Text typesetter，每块最多256个待测行／65,536个UTF-16单元；块间释放临时对象。保持精确字体回退、Tab与组合字符测量、原生选择和既有行／字节上限。
- 最终三次组件测量中位数：十万行准备1.83秒（原2.84秒，约减少36%），准备后进程RSS66.94MB（对照81.48MB）。跳转绘制仍约2秒，尚未解决；不宣称内存峰值或真实UI延迟达标。整文档typesetter与直接TextKit2迁移的实验均未采用：前者准备后RSS约300MB，后者在当前结构下更慢且占用更高。
- 可重复运行scripts/measure-preview-performance.sh；夹具只在工作区根目录的随机专用目录创建并自动清理。实际生产预览源码参与优化编译，独立新进程每样本3次，覆盖200行／1万行／12万源行（展示10万）、4MB单行、2GB稀疏文件。持久化数据：docs/preview-performance-0.4.5.json。非冷缓存、非真实输入延迟，保留实际窗口验收要求。
- 8项预览针对回归通过，包括视口扩大后的新增可见行着色、块边界／大ASCII间隔／超长Unicode行、字体宽度对照、UTF-16偏移和十万行末尾glyph坐标。发布与最终窗口检查另见QA.md。

- 原生滚动视口尺寸变化会主动刷新可见范围的临时语法颜色；解决首次布局或拖动分隔线扩大预览区后，新增行保持黑色的问题。回归验证在不滚动的情况下将120pt视口扩大到600pt，第21行关键词获得正确语义色。
