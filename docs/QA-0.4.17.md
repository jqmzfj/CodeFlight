# 0.4.17 大文件搜索统计

## 问题与修改

原工具栏计算属性在每次SwiftUI重绘时，于主线程对整个已读取文本执行components／filter。十万行单次组件测量，value／missing／中文第分别耗时195／217／342ms，且统计的是命中行数，同一行多次出现只算一次。

- 统计移到独立子视图的可取消detached任务；120ms输入合并只作用于统计，文字输入与可见区域高亮不等待计数。
- 按NSString非重叠、不区分大小写匹配统计实际次数，与现有高亮规则一致；只保留计数，不创建全文件行数组或所有匹配位置数组。
- 查询或文件内容变化时，未完成统计显示省略号及“正在搜索”可访问性值；完成结果绑定输入，取消旧任务并防止过期结果回写。
- 工具提示明确范围为“当前已读取文件内容”，没有宣称扫描未读取的大文件尾部。

## 已有证据

- FileSearchCounterTests 2项通过：重复出现／大小写／非重叠／Unicode／空白／无匹配及取消旧请求。NativeTextPreviewTests 10项回归通过；没有将它们称作本版完整套件回归。
- 优化组件单次测量，三种查询约102／47／138ms，且value正确计数200000；此测量与旧版“命中行数”语义不同，不直接用比例宣称输入加速。
- 同源完整WorkbenchView宿主实际打开99,999条代码行（末尾换行共100000显示行）：value计数199998，missing为0，中文第为99999。搜索期间可见语法高亮保持，切换small.swift后旧查询为0，small查询为3，Esc与⌘F恢复符合既有习惯。
- 未优化宿主搜索后进程RSS采样122.61MB；该值不是峰值或正式包资源承诺。主循环16ms定时器测到长间隔，不能将UI自动化调用时长或定时器间隔等同真实按键到像素延迟；已保留原始证据，优化构建复测5轮missing／value连续输入（期间无AX快照）主循环P95约83ms、最大约130ms；默认模式Timer及自动化动作仍有干扰，不作为真实按键到像素延迟或全产品达标证据。
- 独立可见区域高亮组件的8个查询，更新约1.8–2.6ms，离屏绘制约9–15ms；不能据此宣称完整窗口已达到同样延迟。
- 数据见search-performance-0.4.17.json；日志production-057-*位于.build。

## 最终应用与剩余范围

优化宿主已完成上述实测；arm64／Intel Release无编译警告，Universal 2／严格签名／runtime smoke／最终应用重启通过，保持test1与运行进程250pt。DMG校验、ZIP完整性、ZIP版本0.4.17(60)和可执行文件SHA256一致性通过。夹具已清理。正式应用完成启动复核，搜索操作实测来自同源独立完整工作台宿主。大文件打开和跳转的完整延迟／内存矩阵仍需继续。

- 优化宿主验证Esc后重新⌘F直接输入missing为0，焦点在搜索框；测试项目关闭、宿主退出后核对无宿主进程、Git干净、两个文件逐字符合生成内容；根目录.search-latency-qa已精确删除。

## 2026-10-26 发布产物核验更正

0.4.18复核发现，手工合并Universal二进制时使用了旧的`*-apple-macos`目录；本版本安装包实际仍含0.4.15代码。因此以上双架构源码构建、专项测试与同源宿主交互证据保留有效，但安装包／最终应用检查不能证明本版本新功能已交付。0.4.18发布流程改为SwiftPM查询实际产物路径，并将最终签名应用的两个Mach-O UUID与当前两份构建逐一核对；修复后的交付验证记录见QA-0.4.18.md。
