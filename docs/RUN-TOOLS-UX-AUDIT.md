# 运行与工具交互验收

目标保持原范围：参考 PhpStorm，完善运行、工具以及已有 Git 操作的日常交互，达到自用稳定标准。只在工作区内的临时项目验证；不启动、修改或停止业务项目的代码、Git 操作和进程。原生、轻量、多项目并行。

## 0.3.34 已实现及实际验证

- 只查看 PhpStorm 顶部运行／重跑和停止菜单；其两个现有业务进程保持不变。
- 顶部运行／重跑根据当前配置状态切换，停止入口始终存在。多进程菜单按项目和会话列出单独停止与全部停止。
- 启动自动打开运行工具窗口，选中该会话；配置与任务 ID 关联，重复启动配置聚焦已有实例。
- 单独停止不影响其他进程，显示停止中，结束后显示已停止；重新运行等待旧进程组结束，保留命令、目录、环境。停止可取消待重跑请求。
- 运行会话独立日志与选择，后台项目／其他会话输出不覆盖选中日志；状态、退出码、运行时长可见。
- AppKit 日志视图左对齐、自动换行、文本选择，支持筛选、复制、清空、跟随输出；清空内容在结束时不会复活。关闭已结束会话自动选择剩余会话。
- 自动测试覆盖多进程精确停止、配置去重、独立输出、清空后结束、跨项目重跑快照和取消重跑，原有配置目录／环境及项目关闭测试继续通过。

## 0.3.35 进行中的验收

- 运行配置已实现草稿关闭／Esc三选确认、环境变量行号校验、选择记忆、从项目导入、外部磁盘修改保护。UI实测非法环境变量禁用保存、Esc与继续编辑保留草稿、修正后保存、外部改动阻止覆盖。导入追加及选择重启记忆仍需完整UI复核。
- 服务已实现独立加载／空／失败、失败保留缓存、串行容器操作与失败重试、不覆盖运行输出。模拟客户端测试通过；真实UI只读查看现有Docker列表与开发环境路径，不操作业务容器。真实连接失败和重试的UI还未验收。
- 启动前再次校验目录、命令与环境快照，非法输入不创建会话，不泄露环境变量值；多行和引号作为环境值保留。新增针对测试通过。
- 每条pipe独立保留最多3字节未完成UTF-8尾部，避免中文／emoji跨读取出现替代字符；所有字节切点和真实分片pipe测试通过，保留最终原始输出行为。
- 布局分栏、复位及配置文本区调高已在实际UI验证，见QA.md。

## 0.3.36 日志与退出边界

- 运行输出由独立有界日志缓冲保存，50ms合并一次主线程刷新，最多一个待刷新回调；完成后使队列回调失效，清空共享同一缓冲，避免结束时恢复旧内容。超出12,000 Unicode标量时显示截断提示。
- 常见ANSI颜色／OSC标题和超链接控制符转为纯文本，CR进度覆盖、CRLF、退格与跨块序列保持解析状态；不是完整终端仿真或ANSI颜色渲染。
- pipe采用非阻塞有界排空，主命令退出后不再无限等待继承管道的写端关闭；托管会话及明确停止的命令在完成前清理已核验独立进程组的残留子进程（TERM后KILL）。不追踪主动脱离进程组的daemon。
- 新增解析／截断／清空／批量刷新／队列失效、真实10,000行命令、管道写端保留、后台子进程退出等测试。停止包含忽略TERM的子进程回归通过。
- 实际UI测试20,000行带颜色控制符的中文／emoji及CR进度，看到截断提示、可读文本与100%，清空后仅保留新ready行，顶部停止转为已停止且旧文本未恢复；临时项目已停、关闭、删除。

## 0.3.37 控制台隔离

- Git操作不再写入运行会话的commandOutput／Project.output，按项目保存操作记录，包括开始／结束、结果与退出码，后台项目完成时也保留。
- 控制台支持选择旧记录、筛选、复制、删除当前记录和清空已结束记录；进行中的记录保留。每项最多12,000 Unicode标量，每项目最多20项／64,000标量，关闭项目释放。
- 错误提示关联原操作记录，查看详情定位对应记录；新诊断不会误用旧Git错误上下文。没有可关联记录的诊断单独保存。
- 超时提示同时进入实时流，避免已有输出时仅保存在最终原始结果而被运行日志忽略。
- 针对测试覆盖真实Git失败与持续运行日志隔离、后台记录、历史上限、清空／项目关闭释放、错误上下文及真实命令超时。
- 实际UI：仅在根目录.console-ui-qa执行持续run-tick和指向不存在本地路径的Fetch；错误详情正确打开仓库操作记录／退出码128，运行继续时内容不被覆盖，删除记录不停止进程；最后顶部停止、关闭夹具回test1并删除。

## 0.3.38 补齐的行为与验收

- 退出生命周期：应用准备退出时先取消所有待重跑请求，阻止尚未启动的会话与新的启动，再清理托管进程组。关闭项目同时释放会话选择和该项目的待重跑标识。针对测试覆盖退出时正在等待重跑、另一项目尚未启动的命令、已结束会话重跑前关闭项目，以及取消退出后进程与草稿处理器保持不变。
- 运行配置磁盘一致性：每次打开配置读取最新磁盘快照；拒绝超过1 MB、损坏JSON及重复配置ID，保留文件并禁用保存。实际窗口分别验证重复ID、坏JSON的错误提示和保存禁用；外部新增的第四个配置无需重启即出现在重新打开的列表中。编辑中发生外部修改的保护见0.3.35验收。
- 项目导入：修复初始化任务取消与重入导致首次检测为空。实际首次打开已列出package.json的npm check／dev；追加两项后原配置保留，已导入的同命令／目录项禁用；保存后磁盘顺序与内容正确。选择npm check后重启应用仍选中npm check。
- 环境变量：表单用JSON引号表示换行、引号和反斜杠，并保留传统KEY=VALUE及单引号输入；不会执行变量内容。针对测试覆盖空值、前后空格、中文、多行、Windows路径和字面量shell表达式；实际UI保存后验证磁盘值与输入含义一致。
- 配置草稿退出：菜单与⌘Q先询问草稿，再交给AppKit退出；避免系统先关闭sheet后才询问。实际取消／Esc后原面板和已修改名称仍在，保存并退出后磁盘名称更新且应用退出。关闭面板的保存／丢弃／继续编辑以及外部修改保护沿用既有验收。
- 控制台：按具体Git动作展示获取、推送、暂存、批量操作、远程、工作树、子模块、历史操作与冲突处理名称。诊断中的旧URL用户信息、查询与片段过滤后进入历史、错误提示及完成回调；临时Git认证的原文、URL编码及Basic形式在pipe流与最终结果中被过滤。每个字符边界、逐Unicode标量和真实stdout／stderr分片测试通过，普通输出保持原样。认证测试只用虚构凭据。
- 实际多项目流程：仅在根目录.interaction-ui-a／b运行带中文环境值的持续输出。顶部停止菜单显示两个项目；停止B后A持续输出且B显示已停止。重新启动B后取消关闭保留进程，停止并关闭只关闭B，A持续运行。A重新运行后立即退出，原PID及测试shell均已结束；自动测试同时覆盖尚未排完的重跑请求。没有启动／停止业务项目。
- 服务错误UI：在.build下生成隔离测试宿主，复用生产ServicesTool与WorkbenchModel，仅注入模拟DockerClient。依次实际验证连接错误→重试恢复、刷新失败保留容器、操作失败显示退出码→重试成功更新为Exited；英文深色、600pt窄窗口及空容器提示正常。没有调用真实Docker操作。宿主退出后已删除。
- Git交互回归：隔离仓库实际勾选暂存、提交、提交完成清空输入；12秒测试pre-commit期间显示忙碌指示，暂存、提交、Fetch／推拉与操作菜单禁用。既有Git表单的取消、失败保留输入、重试、危险确认、快照保护和布局验证见QA.md各版本记录；本轮全套测试继续作为回归门禁。
- 外观与键盘：实际查看中文系统浅色的配置／运行／Git页面、英文深色主工作区与服务窗口；1120pt主窗口和600pt服务宿主布局完整，Esc／⌘Q及配置选择已操作。结束时恢复中文、跟随系统、纯色，并回到test1，保留原三个项目标签。

## 验收范围与边界

当前目标是轻量的运行命令管理、服务工具及既有Git日常交互。日志保留有界纯文本，不提供完整PTY终端或ANSI颜色仿真；主动daemonize并脱离进程组的服务不属于托管会话。没有对业务代码、业务Git状态或现有容器做写操作，也未向Gitee写入。服务错误与操作重试使用隔离客户端验收，真实环境读取与认证流程的证据分别见QA.md和既有测试。

最终门禁已完成：210项完整测试零失败，启动冒烟、Universal 2构建与签名校验通过，0.3.38（41）DMG／ZIP已生成。最终通用包重新启动验证原项目标签、配置窗口关闭及无配置引导、中文命令输出与结束状态；会话清理及根目录清理完成。证据详见QA.md的0.3.38条目。
