# 0.4.24 文件预览准备缓存

## 修改

- CodePreview通过PreparedPreviewCache复用最近文件的规范化文本、行号偏移与精确宽度，避免每次切回都重新计算。缓存按文件、字体与单元格宽度隔离，并逐字比较原始文本；内容变化即重新准备，不复用旧的显示／搜索缓冲。
- 最多3项、24MiB保守成本预算，按最近使用淘汰；预算同时计入原始文本、显示文本的UTF-8与潜在UTF-16存储，以及行偏移。此预算是缓存的估算上限，不是整个应用的RSS上限，也不含当前TextKit布局。超预算文件仍正常预览，只不缓存。
- 源内容比较在actor中，准备在独立可取消后台任务中；取消只影响所属文件，不取消其他文件请求。界面发布仍检查任务是否过期。

## 组件测量

- 原始基线：.build/preview-performance/before-prepared-cache.json；新增缓存测量：docs/preview-performance-0.4.24.json（同时输出.build/preview-performance/latest.json），控制台见production-064-performance.log。各样本独立进程，3次取中位数。

- 缓存测量使用独立进程，RSS快照分别约54.94／35.84／36.92MiB；不是主应用RSS或峰值内存。未缓存的TextKit组件大跨度中部首次绘制仍约470ms，优化未解决这一开销。
- 这些数据仅证明准备结果复用，不证明实际点击到屏幕、磁盘冷读取或完整主应用峰值资源达标。
